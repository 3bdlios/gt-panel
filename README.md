# GT Panel 2.0 — Flat Repair Hub

واجهة فلات أكبر مع أيقونة تنزيل وإصلاح، وأقسام Fixes وPlugins وSkins وUpdates، ومساحة لتفاصيل الحزمة والتوافق، ونسخ محلية قابلة للاسترجاع. معاينة docs/GT-Panel-2-flat-preview.png تمثيل للتخطيط وليست لقطة من جهاز فعلي. الواجهة الجديدة وحزمة تثبيتها لم تُختبرا بعد على الرسيفر.

## تثبيت التحديث

انسخ dist/enigma2-plugin-extensions-gtpanel_2.0.0_all.ipk إلى /tmp على جهاز OpenATV، ثم نفّذ عندما تقرر تثبيته:

```sh
opkg install /tmp/enigma2-plugin-extensions-gtpanel_2.0.0_all.ipk
```

بعد النجاح أعد تشغيل الواجهة يدوياً وافتح GT Panel. لا تستخدم force-depends. حزمة DEB مرفقة للصور التي تستعمل dpkg، لكن فحص قبول هذا المشروع مستهدف إلى OpenATV/GT MEDIA COMBO.

الكتالوج الافتراضي الجديد: https://raw.githubusercontent.com/3bdlios/gt-panel/main/manifest-v2.json . إذا كان لديك /etc/gt-panel/repository.json فهو يأخذ الأولوية: غيّر manifest_url فيه إلى الرابط الجديد. تعريف الموديل يقرأ من Device Tree قبل بيانات الصورة؛ لا يحتاج device.json. يتم فحص GitHub مرة عند فتح البلجن، لا عند إقلاع الجهاز. تنزيل حزمة لا يبدأ إلا بعد طلب المستخدم.

## ملفات الرفع إلى GitHub

فك GT-Panel-2.0-GitHub-upload.zip وارفع محتوياته إلى جذر مستودع 3bdlios/gt-panel مع استبدال الملفات التي تختار تحديثها. يجب وجود manifest-v2.json في الجذر، وrepository/gtcombo-android-v1.tar.gz في المسار نفسه. الحزمة الجديدة تقرأ manifest-v2.json؛ يبقى manifest.json القديم منفصلاً للنسخ السابقة حتى لا تتعطل عند رؤية إصلاحات ذات مسارات جديدة.

لا تعني تجهيز ملفات الرفع أنها نُشرت. آخر محاولة كتابة عبر اتصال GitHub رجعت 403 Resource not accessible by integration، لذلك يلزم رفع هذه الملفات من حسابك أو منح الاتصال صلاحية كتابة مناسبة. لا حاجة إلى إرسال رموز دخول في المحادثة.

## إصلاح أندرويد الموجود في الكتالوج

عنصر واحد في Fixes يجمع إصلاح Restart to Android واختيار Android من قائمة الإقلاع. يتضمن ملفات المساعد وإعداد تشغيل القائمة، ولا يشغّل ملف GTCombo-Android-Fix.py تلقائياً. القيم المقيدة: موديل GTMedia GT Combo، صورة openatv 8.0.1.20261007، Python 3.14، ومحمل إقلاع SHA256 مطابق للنسخة المراجعة. يفحص CRC قسم env وbootcmd وعلم bootfromnand قبل استبدال الملفات. يرفض أي ملفات محلية غير معروفة بدلاً من الكتابة فوق تعديلات مختلفة.

الطريقتان نجحتا على جهاز المستخدم في المحادثة، لكن تطبيقهما عبر محرك الحزم الجديد لم يختبر على الرسيفر بعد. يحتاج قبولاً على نسخة USB تجريبية قبل التوزيع العام. عند تركيب الحزمة لا يكتب البلجن /dev/env ولا يعيد التشغيل. لاحقاً، عند اختيار أندرويد صراحة، يحفظ المساعد نسخة من البيئة ثم يكتب علم الإقلاع لمرة واحدة إلى القسم الداخلي؛ المحمل يعيده إلى الصفر قبل إقلاع أندرويد. انقطاع الكهرباء أثناء هذه الكتابة قد يتلف البيئة، ولا توجد معاملة ذرية ضد فقد الطاقة. احتفظ بنسخة USB ونسخة بيئة الإقلاع خارج الجهاز.

لا تُنشر ملفات cfgload التجريبية السابقة كإصلاح معتمد؛ لم تحل المشكلة. هذه الحزمة تستخدم آلية bootfromnand التي نجحت فعلياً. لا تتغير مصادر التحديث الرسمية أو إعدادات تحديثاتها.

## إضافة إصلاح مستقبلي دون تحديث البلجن

نظام الإصلاحات الآن قائم على البيانات والملفات. لإصلاح يستخدم القدرات الحالية: جهز الملفات النهائية ووصف JSON، أنشئ الأرشيف، ثم ارفع الأرشيف وأضف العنصر إلى manifest-v2.json. لا يتطلب تغيير كود GT Panel لكل حزمة. تحتاج مراجعة المسارات والتوافق والبصمات قبل النشر. تنفيذ نوع عمليات جديد غير مدعوم يحتاج تطوير المحرك؛ هذا لا يعادل تحديثاً لكل إصلاح.

لا يشغّل المحرك سكربت تثبيت عشوائياً من الإنترنت. حزم الإصلاح توصف بملفات نهائية وفحوص توافق، ثم تُنسخ بعد تأكيد المستخدم. يمكن أن تتضمن ملفات كود تعمل لاحقاً؛ لذلك لا يغني SHA256 عن الثقة بمصدر المستودع ومراجعة المحتوى. الكتالوج غير موقع بمفتاح مستقل؛ اختراق المستودع قد يغيّر الحزمة والبصمة معاً.

راجع docs/REPAIR-FORMAT.md لصيغة وصف الإصلاح وtools/pack_repair.py للبناء.

## النسخ والاسترجاع

قبل استبدال الملفات، يحفظ المحرك النسخ السابقة وأذوناتها وبصماتها وقائمة الملفات الجديدة تحت /var/lib/gt-panel. الزر الأزرق يعرضها، ثم OK وتأكيد للاسترجاع. الاسترجاع يكتب فوق تعديلات لاحقة في نفس الملفات، ولا يسترجع /dev/env لأن محرك التثبيت لا يكتبه. ملفات البيئة التي يحفظها مساعد أندرويد منفصلة تحت /etc/gtcombo-env-backup-*.

عند فشل الكتابة العادي يحاول المحرك الرجوع للنسخ السابقة. بعد فقد الكهرباء قد تبقى عملية جزئية وقفل install.lock؛ لا تزيل القفل حتى تتأكد من توقف عملية التثبيت، وتراجع journal.json ونسخ الملفات. الاستبدال ذري لكل ملف فقط، وليس معاملة ذرية لكل الحزمة أو ضماناً ضد انقطاع الطاقة. ملفات النسخ القديمة من الإصدار 1 قد لا تحتوي بصمات تحقق؛ النسخ الجديدة تتحقق قبل الاسترجاع.

## البناء والتحقق

```sh
python3 -m unittest discover -s tests -v
python3 tools/build.py
```

نجح 20 اختباراً محلياً: التوافق، حظر المسارات والروابط غير المسموحة، رفض الأرشيفات الخطرة والعبث بالبصمات، نسخ واسترجاع الملفات والأذونات، رفض النسخ التالفة، CRC البيئة، وفحص حدود التخطيط لشاشات FHD وHD ودقات أصغر. لا محاكاة كاملة لـ Enigma2 أو U-Boot. لا تعتبر النجاح المحلي اختباراً فعلياً للتثبيت على الرسيفر.
